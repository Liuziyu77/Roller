### Sphinx 增量构建坑：侧边栏标题 stale（已遇到并修复）

- 现象：逐个改多个文档标题时，autobuild 增量构建导致"兄弟页面"侧边栏（globaltoc）里嵌入的标题是旧快照（Sphinx 不会因子文档改标题而重建兄弟页面的 sidebar）。
- 修复：停两个 autobuild → `rm -rf docs/_build` → 重启（全量重建）。用户报告"侧边栏标题不一致"时直接全量重建即可。

### 侧边栏展开机制与跨页跳转收起 bug（已修复）

- 主题：sphinx_rtd_theme + `collapse_navigation: False`，但 `docs/_static/custom.css` 完全接管展开逻辑：子菜单只在 `li.roller-expanded` 时显示（`li.current` 也不例外，CSS 第 18-28 行）。
- `roller-expanded` 是纯 JS 点击状态（`sidebar-scroll.js` 的 `toggleSection`，展开时收起兄弟节点=手风琴）。页面跳转 = 整页重载 → 类丢失 → 当前页分支收起。
- **修复**（`sidebar-scroll.js`）：新增 `expandCurrentBranch()`，在 `initialize()` 里最先执行 + **MutationObserver 回调里也执行**（theme.js 加载后动态注入 toctree-expand 按钮、reset() 重排 current，observer 每次重申展开状态），自动给 `l1/l2/l3.current` 加 `roller-expanded` 并同步按钮 aria。注意 `nav` 是 `initialize` 局部变量，函数内要用 `document.querySelectorAll`（第一次就踩了这个作用域坑，靠读回文件发现）。
- **第二个坑（关键！）：改 `_static` 下的 html_js_files 文件，Sphinx 增量构建只复制新文件、不重新渲染 HTML** → 页面继续引用旧 `?v=` hash → 浏览器加载缓存旧 JS → 修复"看似没生效"。用户报告"改了没用"时先查：`HTML 里的 ?v=` vs `md5sum 实际文件`，不一致就是没部署。修复 = `rm -rf _build` 全量重建。**每次改 _static 下的 js/css 后都要全量重建。**
- 排查命令：`curl -s 页面 | grep -o 'sidebar-scroll.js?v=[a-f0-9]*'` 对比 `md5sum _build/html/_static/sidebar-scroll.js`。
- 遗留认知：`_static` 自定义 JS 带 Sphinx 内容 hash（`?v=427d1113` 形式），文件变 hash 才变，但前提是 HTML 重渲染了。
- 页面切换白闪 = 静态站整页导航，无法消除（除非 pjax，不建议）。
